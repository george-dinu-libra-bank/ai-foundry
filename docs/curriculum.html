AI Engineering on Azure

From your first model call to a working AI assistant for banking — in seven sessions.

This module takes you through the full craft of building AI applications on Microsoft Azure: models and how to talk to them, prompts and how to judge them, documents and data, multi-step workflows, and shipping to the cloud. Session by session, you grow one application — Libra Assist, a banking assistant — from a single authenticated call into an end-to-end solution.

Session 1 · Wed 22 Jul · 09:30–12:00 · discussion day

Foundations — Python, GenAI & your Azure environment

The discussion day: we meet each other, set expectations, and build the module's mental map — no laptops, all concepts. Everything later sessions do with your hands, this session first puts in your head.

  • Welcome & introductions — who you are, what you want from these two weeks
  • Why Python is the language of AI
  • Generative AI concepts: models, tokens, embeddings, prompts — and their limits
  • Generative AI live in code — tokens counted, a model call, embedding similarity, demonstrated
  • Cloud architecture — what actually changes when software moves to the cloud
  • A guided tour of Azure: regions, resource hierarchy, Entra ID, portal, CLI & Copilot
  • Microsoft Foundry: a tour of the AI platform, and how it differs from Azure OpenAI

You leave with: the mental map for everything we build — and a checklist to prepare your environment for Session 2.

Session 2 · Thu 23 Jul · 09:30–12:00 · hands-on begins

Microsoft Foundry — models, gateways & your first deployment

Hands-on begins. Why enterprises consume models through a gateway rather than calling providers directly, what that buys a bank — and by the end of the morning, a model you deployed yourself answering your first authenticated calls.

  • What Microsoft Foundry is, and what an LLM gateway does
  • Using models provider-direct vs through Azure — privacy, compliance, cost
  • The third lane: hosting models locally — when and why
  • Walkthrough: the Foundry portal — model catalog, deployments, playground
  • Lab: your first authenticated gpt-5.1 call from Python
  • How we'll build from here: AI-assisted, spec-driven development — an introduction

You leave with: a model deployment you understand end to end, and your first real calls against it.

Session 3 · Fri 24 Jul · 09:30–12:00

Model Integration & Inference — LLMs in applications, model selection & trade-offs

The model becomes a dependency inside real software: SDKs, parameters, structured outputs, failure handling — and the application skeleton arrives, built spec-first with an AI coding agent, then running on your machine.

  • The SDK surface: talking to Foundry models from Python
  • Anatomy of a chat completion: messages, roles, parameters
  • Structured outputs and streaming; handling failures like an engineer
  • Choosing a model: the quality / latency / cost triangle
  • Walkthrough: an application skeleton built spec-first with an AI coding agent
  • Lab: run the starter app — Python API + web chat — on your machine

Session 4 · Mon 27 Jul · 09:30–12:00

Azure Foundry in Practice — the tools, the platform, your own environment

The hands-on day: you stop borrowing an environment and build your own. The command line and the SDK, why engineers use them instead of a website and a pasted key, and how every part of the platform is reached from your own code.

  • What a CLI and an SDK actually are — and why not the portal or an API key alone
  • Lab: install the toolchain, sign in, prove your identity works
  • Resources, resource groups & why the region you choose is an engineering decision
  • The two portals: portal.azure.com vs ai.azure.com
  • Every section of the Foundry menu — Agents, Models, Fine-tune, Services, Tools, Knowledge, Memory, Data, Evaluations, Guardrails
  • One key for everything? Wiring each surface from code, keylessly
  • Lab: create your own resource group, resource and deployments — and run the course application against them

You leave with: an Azure environment you built, own and can rebuild from a script.

Session 5 · Tue 28 Jul · 09:30–12:00

Data Integration & RAG — vector stores, embeddings & grounding with Azure AI Search

The assistant learns your documents and gains memory: retrieval-augmented generation with citations on one side, an Azure SQL database persisting conversations and costs on the other.

  • Embeddings and chunking: how documents become searchable meaning
  • Vector stores, Azure AI Search, and answering with citations
  • Data integration: provisioning an Azure SQL database and connecting from Python
  • Lab: ground the assistant in a banking document set — and persist chat history and token spend to your own database
  • Prompt design and measuring answer quality — evaluating what retrieval changed

You leave with: an assistant that answers from documents and remembers its conversations.

Session 6 · Wed 29 Jul · 09:30–12:00

Orchestration & Agentic Workflows — multi-step pipelines & automation

From answering to acting: the agent loop, tools, and the guardrails that keep autonomy inside an approval boundary — plus the automation that ships the app to Azure in a container.

  • When one call isn't enough: workflows vs agents — principles, then Azure specifics
  • Tool calling; guardrails and approval gates
  • Foundry Agent Service and multi-step pipelines
  • Automation: containerize the app and deploy to Azure — registry to Container Apps
  • Lab: give your assistant tools — query your database, look up documents

You leave with: an assistant that acts — and a deployment pipeline into the cloud.
